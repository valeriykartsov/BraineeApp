# Архитектурные решения BraineeApp

Формат: контекст → варианты → рекомендация → статус.
Статусы: **Предложено** (ждёт подтверждения владельца), **Принято**, **Отклонено**, **Заменено**.

---

## D-01. Порядок модернизации: страховка и домен до смены хранилища
- **Контекст:** persistence-слой без тестов, бэкапа для пользователя нет, мутации продублированы (аудит R2, R7, R11).
- **Варианты:** (а) сразу SwiftData persistent; (б) сначала тесты, экспорт, `TaskService`, новые поля.
- **Рекомендация:** (б). Дольше на 4–6 небольших PR, но миграция пройдёт по проверенному пути с возможностью отката.
- **Статус:** Предложено.

## D-02. Роль Keychain
- **Контекст:** сейчас Keychain хранит полные JSON-документы (включая аватар) как бэкап, переживающий переустановку (`KeychainStorage`, `AppDataStore`). Бриф: Keychain — только секреты.
- **Варианты:** (а) сохранить Keychain-зеркало данных навсегда; (б) после стабильной миграции прекратить запись (SD-4), позже удалить записи (SD-6) с подтверждения; бэкап — файлы JSON.
- **Рекомендация:** (б). Обратите внимание: вы потеряете автоматическое восстановление данных после **удаления и переустановки** приложения. Замена — ручной/авто-бэкап в Files (iCloud Drive).
- **Вопрос владельцу:** важно ли переживать переустановку без ручного бэкапа?
- **Статус:** Предложено.

## D-03. Новые поля модели до постоянной схемы
- **Контекст:** нет `updatedAt`, `completedAt`, `UserProfile.uuid` (аудит R4, R5).
- **Рекомендация:** добавить в JSON v9 и модели до SD-1. Значения для старых записей: `updatedAt = createdAt`; `completedAt = nil` (для уже выполненных задач дата закрытия неизвестна — в отчётах `/closed` они не появятся или появятся с пометкой).
- **Вопрос владельцу:** для старых выполненных задач ставить `completedAt = nil` или `= createdAt`? Рекомендую `nil` — честнее.
- **Статус:** Предложено.

## D-04. Когда JSON перестаёт быть основным
- **Рекомендация:** после SD-3 минимум 7 дней ежедневного использования без проблем, затем SD-4. Автобэкап JSON — при уходе в фон, не чаще раза в 24 часа, хранить последние 7 файлов в `Application Support/Backups/`.
- **Статус:** Предложено.

## D-05. Тип объекта для календаря
- **Контекст:** сравнение в `target-architecture.md` §4.1.
- **Варианты:** EventKit events; EventKit reminders; Google Calendar/Tasks API.
- **Рекомендация:** EventKit **events**, односторонний экспорт. Reminders не попадают в Google; Google API требует OAuth и сеть.
- **Проверить на устройстве (CAL-1):** запись в календарь Google-аккаунта, стабильность `eventIdentifier`, возможность создать отдельный календарь.
- **Статус:** Предложено.

## D-06. Правила событий календаря
- **Вопросы владельцу:**
  1. Длительность события для задачи со временем: 30 мин (рекомендация), 15 мин или 1 час?
  2. Выполненная задача: удалять событие (рекомендация) или оставлять с префиксом «✓»?
  3. Мягко удалённая задача: удалять событие (рекомендация).
- **Статус:** Предложено.

## D-07. Tombstones
- **Рекомендация:** вводить вместе с синхронизацией (SYNC-1), не раньше. До этого окончательное удаление остаётся бесследным, как сейчас.
- **Статус:** Предложено.

## D-08. Рендер Markdown
- **Варианты:** (а) собственный блочный парсер + `AttributedString(markdown:)`; (б) SPM-пакет (например, Apple `swift-markdown` для разбора); (в) `WKWebView` + JS-библиотека.
- **Рекомендация:** (а) — без зависимостей, достаточно для заметок; (б) — если (а) окажется недостаточным для таблиц/вложенных списков; (в) — только при реальной необходимости.
- **Статус:** Предложено.

## D-09. Направление и объём синхронизации
- **Варианты:** (а) односторонняя iPhone → сервер, сервер — read-only реплика для отчётов; (б) двусторонняя.
- **Рекомендация:** (а). Telegram-бот только читает, других пишущих клиентов нет — конфликтов не возникает. Двусторонняя — отдельное решение при появлении сценария.
- **Вопрос владельцу:** синхронизировать ли привычки (нужны ли они в Telegram-отчётах)?
- **Статус:** Предложено.

## D-10. Доступ к SQLite на сервере
- **Варианты:** `sqlite3` из стандартной библиотеки + SQL-миграции; SQLAlchemy Core; SQLModel/ORM + Alembic.
- **Рекомендация:** `sqlite3` + пронумерованные SQL-файлы и таблица `schema_version`. Меньше зависимостей и «магии»; легко читать.
- **Статус:** Предложено.

## D-11. Сетевой путь iPhone → MacBook
- **Варианты:** (а) локальная Wi-Fi сеть по HTTP (исключение ATS `NSAllowsLocalNetworking`, разрешение локальной сети); (б) Tailscale (работает вне дома, HTTPS); (в) публичный туннель — не рекомендуется.
- **Рекомендация:** начать с (а) для разработки; (б), если нужна синхронизация вне дома.
- **Вопрос владельцу:** нужна ли синхронизация вне домашней сети?
- **Статус:** Предложено.

## D-12. Процесс Telegram-бота
- **Варианты:** фоновая задача внутри процесса FastAPI; отдельная команда с той же БД.
- **Рекомендация:** отдельная команда `python -m app.telegram` — проще отлаживать и перезапускать; общий код — `ReportService`.
- **Статус:** Предложено.

## D-13. Платформы таргета
- **Контекст:** основной таргет объявляет macOS и visionOS (`SUPPORTED_PLATFORMS`), но код использует `UIKit` без условий в `AppDelegate.swift`; сборка под эти платформы не проверялась.
- **Рекомендация:** оставить как есть до отдельной задачи; не тратить время на поддержку macOS/visionOS, если они вам не нужны.
- **Вопрос владельцу:** нужны ли macOS/visionOS?
- **Статус:** Предложено.

## D-14. Инструменты Claude Code
- **Рекомендация:** пока только `CLAUDE.md`. Skills/hooks/MCP/subagents не создавать; кандидат на будущее — skill «запусти тесты и покажи итог» после 2–3 повторений вручную.
- **Статус:** Предложено.
