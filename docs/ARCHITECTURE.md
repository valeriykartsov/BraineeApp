# Архитектура BraineeApp

Фактическое устройство приложения на 2026-10-21 (`main`). Решения и их причины — в [`decisions.md`](decisions.md) (D-xx).

## Принципы

1. **Offline-first.** Всё, кроме LLM, работает без сети. LLM — необязательная надстройка; без ключа приложение работает как обычно.
2. **Один источник правды** — постоянное хранилище SwiftData на устройстве.
3. **Одно место для каждого правила.** Изменения данных — только через сервисы `Domain/`; экраны их не меняют.
4. **Внешний идентификатор** — `uuid` (не `PersistentIdentifier`).
5. **Сохранность данных важнее скорости.** Хранилище при старте никогда не очищается; перед заменой данных — бэкап.
6. **Без сторонних зависимостей** — только Apple SDK.

## Слои и папки

Отдельных Swift-пакетов нет: границы — папки и типы внутри таргета `BraineeApp`.

| Папка | Что внутри | Не должен |
|---|---|---|
| `Views/` | Экраны SwiftUI: Задачи (список, канбан), Календарь, Привычки, LLM, Профиль, Матрица | Менять модели и вызывать побочные эффекты напрямую |
| `Domain/` | Сервисы изменений и их правила (статусы, порядок, корзина) | Знать о SwiftUI |
| `Models/` | `@Model`-классы (`TaskItem`, `TaskGroup`, `TaskTag`, `Habit`, `UserProfile`) и перечисления | Содержать сценарии |
| `Persistence/` | Контейнер и схема (`ModelContainerFactory`, `Schema/`), побочные эффекты (`AppSideEffects`), бэкап и восстановление, `StoreContents`, `KeychainStorage` | Содержать бизнес-правила |
| `Integrations/Calendar/` | Экспорт задач в календарь «BraineeApp» и чтение встреч дня (EventKit) | Сохранять или передавать чужие события |
| `Integrations/LLM/` | Клиент OpenRouter, сценарии чата (черновик, разбор, итоги, план дня) | Получать `ModelContext` и менять данные |
| `Integrations/Secrets/` | `SecretStore` — ключи в отдельном Keychain-сервисе | — |
| `Utilities/` | Уведомления, наклейка, виджет-снимок, настройки UI, дизайн-система | — |
| `Debug/` | Только Debug: демо-данные для скриншотов (`-SeedDemoData`) | Попадать в Release |
| `BraineeAppWidget/`, `BraineeShared/` | Виджеты WidgetKit и общий снимок данных | — |

## Хранение

- **SwiftData**, файл `Application Support/BraineeApp/BraineeApp.store`, схема `SchemaV1` (`VersionedSchema` + `BraineeMigrationPlan`), `#Unique` на `uuid` во всех моделях (вставка с существующим `uuid` — обновление, а не дубль). CloudKit выключен.
- **Новые поля** — только новой версией схемы (`SchemaV2` + этап миграции, классы V1 «заморозить», D-17).
- **Мягкое удаление** — флаг `isSoftDeleted` (в JSON бэкапа — `isDeleted`); окончательное удаление — только из корзины.
- **UserDefaults** — только настройки интерфейса (тема, акцент, вкладки, уведомления, модель LLM, согласие на «План дня»).
- **Keychain** — только секреты: ключ OpenRouter (`<bundle id>.secrets`, только это устройство, в бэкап не входит).
- **Старт:** `AppRootView` → `AppDataPersistence.bootstrap` (акцент при первой установке, удаление остатков старого JSON-хранения после подтверждённого переноса, снимок виджета). Хранилище при старте не очищается; ошибка открытия — экран ошибки, а не падение.

## Побочные эффекты изменений

Сервис меняет модели и вызывает `modelContext.didChange()` (`AppSideEffects`):

1. `save()`;
2. снимок для виджетов (App Group);
3. пересчёт локальных уведомлений и наклейки на иконке;
4. сверка календаря «BraineeApp», если экспорт включён.

В тестах сервисам передаётся свой `onChange`, поэтому уведомления и календарь не трогаются.

**Виджеты.** `WidgetSnapshotBuilder` собирает `WidgetSnapshot` (задачи на сегодня, приоритетные, счётчики, привычки) и пишет его в App Group; расширение `BraineeAppWidget` только читает этот файл. Шесть виджетов: четыре для экрана «Домой» (S / S / M / L) и два для экрана блокировки — «Календарь» (`accessoryCircular`: день недели, число, задачи «осталось/всего» с дедлайном сегодня) и «Сегодня» (`accessoryRectangular`: прогресс привычек и задач). Таймлайн обновляется раз в 30 минут и в полночь; если снимок собран не сегодня, виджеты экрана блокировки не показывают его счётчики (задачи — «—», привычки — 0 отмечено). Виджеты экрана блокировки открывают `braineeapp://calendar` → `NotificationDeepLinkRouter.openCalendarToday()` → вкладка «Календарь» на сегодняшнем дне (если вкладка скрыта — «Задачи»).

## Бэкап и восстановление

- **Формат** — один JSON `BackupDocument` (`format = "braineeapp.backup"`, `version = 1`): задачи (включая корзину), папки, теги, привычки, профиль, тема и акцент. Аватар не входит (D-16).
- **Ручной экспорт** — «Профиль → Хранение данных», через «Файлы».
- **Автобэкап** — при уходе в фон, не чаще раза в 24 часа, последние 7 файлов в `Application Support/Backups/auto/` (D-04).
- **Восстановление** — только «заменить всё»: предпросмотр → подтверждение → текущее состояние сохраняется в `Backups/pre-restore/` → замена через `StoreContents.replace` → проверка по каждому `uuid` (D-20).
- **Обратная совместимость** — новые поля JSON читаются через `decodeIfPresent` со значением по умолчанию; старые бэкапы должны читаться.

## Экспорт в Календарь (EventKit)

Односторонний экспорт в собственный календарь «BraineeApp» (iCloud, иначе локальный), D-05/D-06/D-22/D-23:

- событие есть только у активной задачи с датой; без времени — на весь день, со временем — 30 минут; выполненные и удалённые задачи из календаря убираются;
- после каждого `didChange()` и при возврате в приложение `CalendarExportService` сверяет весь список задач с календарём; неизменённые события не переписываются;
- связи «задача → событие» — служебный файл `Application Support/BraineeApp/calendar-links.json` (не SwiftData, не бэкап); потерянные связи восстанавливаются по метке `braineeapp://task/<uuid>` в url события; эта же ссылка открывает задачу в приложении;
- выключение экспорта только останавливает обновление; в событиях нет напоминаний (их присылает приложение).

### Встречи из Календаря (D-37)

Настройка «Профиль → Настройки → Календарь → Встречи из Календаря» (UserDefaults `calendarMeetingsEnabled`, по умолчанию выключена; при включении — запрос полного доступа, общий `EKEventStore` с экспортом). Во вкладке «Календарь» под задачами выбранного дня — блок «Встречи»:

- `CalendarMeetings` читает события всех календарей, кроме «BraineeApp», при показе дня, смене дня, возврате в приложение и по `EKEventStoreChanged`; ничего не сохраняет (ни SwiftData, ни файлы, ни бэкап) и никуда не передаёт (LLM и виджеты встреч не видят);
- правила дня — `CalendarMeetingRules` (чистые функции, тесты): «Весь день» первыми, дальше по времени начала; встреча, начавшаяся накануне, — «до ЧЧ:ММ»; слева время и продолжительность;
- только просмотр: открыть, изменить или удалить встречу из приложения нельзя.

## LLM (OpenRouter)

Вкладка «LLM» — чат с четырьмя режимами (выбор — меню над полем ввода). Ответы «Итоги» и «План дня» можно скопировать обычным текстом (`LLMAnswerText`, только буфер обмена). Провайдер — только OpenRouter, ключ — в Keychain, модель — строка в настройках (по умолчанию `openrouter/auto`). Каждый запрос отправляется отдельно, без истории; история чата живёт только в памяти до закрытия приложения.

| Режим | Что делает | Что уходит в OpenRouter | Меняет данные? |
|---|---|---|---|
| Задача | Фраза → черновик задачи | Текст, дата, часовой пояс, названия папок и тегов | Только после «Сохранить» в обычной форме |
| Разбор | Текст до 3000 символов → до 10 черновиков | То же | Каждый черновик — отдельно, через форму |
| Итоги | Цифры за сегодня или неделю + короткий комментарий | Только числа (посчитаны кодом) | Нет |
| План дня | Порядок задач на сегодня и советы | Номер, название, приоритет, время срока, просрочка задач на сегодня и просроченных (до 30); нужно согласие | Нет |

Как устроено:

- `LLMProvider` (протокол) → `OpenRouterProvider` (`URLSession`, тайм-аут 30 с). Ошибки (нет сети, ключ, лимит, модель, сервер, тайм-аут, битый или пустой ответ) превращаются в понятные сообщения; автоматических повторов нет, есть «Повторить».
- Ответ модели — JSON по схеме из инструкции; код всегда проверяет его сам (D-25). Теги и папки — только существующие; модель видит номера задач, а не `uuid`.
- Каждый запрос просит `reasoning: {effort: "low", exclude: true}`. Для бесплатных моделей (`openrouter/free`, `…:free`) лимит ответа ×4: все они рассуждающие и тратят лимит на рассуждения. Если лимит кончился раньше текста — отдельная ошибка с названием модели.
- «Профиль → Настройки → LLM»: ключ, модель, «Проверить соединение», остаток лимита ключа (`GET /api/v1/key`), отзыв согласия на «План дня».
- **Отладочная заглушка:** в Debug-сборке аргумент запуска `-LLMStub` подменяет OpenRouter готовыми ответами — ключ и сеть не нужны (см. [`TESTING.md`](TESTING.md)).

## Навигация

Вкладки: Задачи → Календарь → LLM → Привычки → Профиль. Календарь, LLM и Привычки включаются в «Профиль → Настройки → Панель вкладок». Матрица Эйзенхауэра — в «Профиль → Дополнительно», открывается листом со своей навигацией.
