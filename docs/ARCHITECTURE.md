# Архитектура BraineeApp

Фактическое устройство приложения на 2026-10-21 (`main`). Решения и их причины — в [`decisions.md`](decisions.md) (D-xx).

## Принципы

1. **Offline-first.** Всё, кроме LLM, работает без сети. LLM — необязательная надстройка; без ключа приложение работает как обычно.
2. **Один источник правды** — постоянное хранилище SwiftData на устройстве.
3. **Одно место для каждого правила.** Изменения данных — только через сервисы `Domain/`; экраны их не меняют.
4. **Внешний идентификатор** — `uuid` (не `PersistentIdentifier`).
5. **Сохранность данных важнее скорости.** Хранилище при старте никогда не очищается; перед заменой данных — бэкап.
6. **Без сторонних зависимостей** — только Apple SDK.

## Слои и папки

Отдельных Swift-пакетов нет: границы — папки и типы внутри таргета `BraineeApp`.

| Папка | Что внутри | Не должен |
|---|---|---|
| `Views/` | Экраны SwiftUI: Задачи (список, канбан), Календарь, Привычки, LLM, Профиль, Матрица | Менять модели и вызывать побочные эффекты напрямую |
| `Domain/` | Сервисы изменений и их правила (статусы, порядок, корзина) | Знать о SwiftUI |
| `Models/` | `@Model`-классы (`TaskItem`, `TaskGroup`, `TaskTag`, `Habit`, `UserProfile`) и перечисления | Содержать сценарии |
| `Persistence/` | Контейнер и схема (`ModelContainerFactory`, `Schema/`), побочные эффекты (`AppSideEffects`), бэкап и восстановление, `StoreContents`, `KeychainStorage` | Содержать бизнес-правила |
| `Integrations/Calendar/` | Экспорт задач в календарь «BraineeApp» и чтение встреч дня (EventKit) | Сохранять или передавать чужие события |
| `Integrations/LLM/` | Клиент OpenRouter, сценарии чата (черновик, разбор, итоги, план дня) | Получать `ModelContext` и менять данные |
| `Integrations/Secrets/` | `SecretStore` — ключи в отдельном Keychain-сервисе | — |

| `Debug/` | Только Debug: демо-данные для скриншотов (`-SeedDemoData`) | Попадать в Release |
| `BraineeAppWidget/`, `BraineeShared/` | Виджеты WidgetKit и общий снимок данных | — |

## Хранение

- **SwiftData**, файл `Application Support/BraineeApp/BraineeApp.store`, схема `SchemaV2` (`VersionedSchema` + `BraineeMigrationPlan`, `Persistence/Schema/Schema.swift`), `#Unique` на `uuid` во всех моделях (вставка с существующим `uuid` — обновление, а не дубль). CloudKit выключен.
- **Модели V2** — `TaskItem` (+ `durationMinutes: Int?`, nil — «не выбрана», для задачи со временем это 30 мин, правила и список — `TaskDuration`, D-40; + `subtasks`), `TaskSubtask` (`uuid`, текст, отметка, порядок; удаляется вместе с задачей при окончательном удалении, корзина её не трогает), `TaskGroup`, `TaskTag`, `Habit`, `UserProfile`. Длительность выбирается в форме задачи (строка «Длительность» под «Время»: 30 мин…3 ч), убрали время или дату — `TaskService` её сбрасывает; больше нигде не показывается и наружу не уходит (D-40). Подзадачи (D-41) редактируются в форме задачи (раздел «Подзадачи»: чекбокс, текст, удаление, «Добавить подзадачу») и сохраняются вместе с ней: `TaskService` приводит их к списку формы по `uuid`; правила (не больше 10, до 50 символов, пустые отбрасываются) — `TaskSubtaskRules`. В строке задачи — счётчик «☑ 2/5» (настройка отображения «Подзадачи»). Отметка всех подзадач задачу не закрывает; наружу подзадачи не уходят.
- **Карточка задачи** (п. 37) — `TaskRowView`, одна для списка, канбана, «Календаря» и матрицы: чекбокс, название в 1 строку, описание до 2 строк, метки (`TaskCardMeta`: срок, статус, приоритет, до 3 тегов, подзадачи — в этом порядке) одним потоком `TagFlowLayout`: не поместившаяся метка переносится на следующую строку, слишком длинная обрезается «…», «корзина». Нажатие открывает форму, «корзина» удаляет в корзину только после подтверждения (подтверждение внутри карточки). Меню долгого удержания и свайпа нет; в списке и канбане долгое удержание начинает перенос всей карточки (`.draggable`). Отступы и красный фон просрочки задаёт сама карточка — у просроченной тот же размер.
- **Переход V1 → V2 (D-39)** — `SchemaUpgrade.openStore()` в `BraineeAppApp`: есть маркер `BraineeApp/schema-v2-migration.json` — просто открыть; нет хранилища — открыть и поставить маркер; иначе копия файлов SQLite + снимок данных схемой V1 (только чтение) в `Backups/pre-schema-v2/` (`backup.json` — формат ручного экспорта, с аватаром; `contents.json` — точные даты для сверки) → лёгкая миграция → сверка каждой записи (`StoreContents.verify`) → маркер. Сбой — экран ошибки без маркера; повтор сверяет с уже сохранённым бэкапом и не создаёт второй.
- **Новые поля** — только новой версией схемы (`SchemaV3` + этап миграции, V2 «заморозить» по образцу V1, D-17).
- **Мягкое удаление** — флаг `isSoftDeleted` (в JSON бэкапа — `isDeleted`); окончательное удаление — только из корзины.
- **UserDefaults** — только настройки интерфейса (тема, акцент, вкладки, уведомления, модель LLM, согласия на «План дня» (`llmDayPlanConsentV2`) и «Матрицу»). Исключение (D-45): текстовый статус профиля `profileStatus` (`ProfileStatus`: до 60 символов, одна строка) — меняется через `ProfileService.update`, входит в бэкап; при следующей версии схемы — в `UserProfile`.
- **Keychain** — только секреты: ключ OpenRouter (`<bundle id>.secrets`, только это устройство, в бэкап не входит).
- **Старт:** `AppRootView` → `AppDataPersistence.bootstrap` (акцент при первой установке, удаление остатков старого JSON-хранения после подтверждённого переноса, снимок виджета). Хранилище при старте не очищается; ошибка открытия — экран ошибки, а не падение.

## Побочные эффекты изменений

Сервис меняет модели и вызывает `modelContext.didChange()` (`AppSideEffects`):

1. `save()`;
2. снимок для виджетов (App Group);
3. пересчёт локальных уведомлений и наклейки на иконке;
4. сверка календаря «BraineeApp», если экспорт включён.

В тестах сервисам передаётся свой `onChange`, поэтому уведомления и календарь не трогаются.

**Виджеты.** `WidgetSnapshotBuilder` собирает `WidgetSnapshot` (задачи на сегодня, приоритетные, счётчики, привычки) и пишет его в App Group; расширение `BraineeAppWidget` только читает этот файл. Шесть виджетов: четыре для экрана «Домой» (S / S / M / L) и два для экрана блокировки — «Календарь» (`accessoryCircular`: день недели, число, задачи «осталось/всего» с дедлайном сегодня) и «Сегодня» (`accessoryRectangular`: прогресс привычек и задач). Таймлайн обновляется раз в 30 минут и в полночь; если снимок собран не сегодня, виджеты экрана блокировки не показывают его счётчики (задачи — «—», привычки — 0 отмечено). Виджеты экрана блокировки открывают `braineeapp://calendar` → `NotificationDeepLinkRouter.openCalendarToday()` → вкладка «Календарь» на сегодняшнем дне (если вкладка скрыта — «Задачи»).

## Журнал сессии

`SessionLog` (п. 16) — записи о действиях пользователя с запуска приложения: только в памяти (не SwiftData, не файл, не бэкап), до 500 последних, новые сверху; никуда не отправляется. Экран — «Профиль → Дополнительно → Журнал сессии».

- Данные: записи делают сервисы `Domain/` в момент изменения (у сервисов есть свойство `log`, в тестах — свой экземпляр). Изменение задачи — строки «поле: было → стало» (`TaskLogFields`); описание — только «Описание изменено»; статус профиля — только «Статус изменён» (D-45); подзадачи — одна строка с числами «Подзадачи: +2, −1, изменено 1, отмечено 1, снято 1» без текста; сохранение формы без правок и перестановка порядка не пишутся, перенос в другую папку пишется.
- Настройки и тема (`@AppStorage` на экранах): `SettingsChangeObserver` следит за фиксированным списком ключей UserDefaults и пишет только реально изменившиеся значения. Служебные ключи (время синхронизации, флаги запуска) и копия режима наклейки для таб-бара не отслеживаются — одно изменение даёт одну запись. Наблюдатель запускается в `AppRootView` после подготовки данных и демо-данных.
- Бэкап: ручной экспорт — после успешного сохранения файла; автобэкап — только когда файл действительно создан; восстановление — одна запись (тема и акцент из бэкапа, если отличаются, — отдельными записями наблюдателя). Ключ OpenRouter — только факт «сохранён» / «удалён».

## Бэкап и восстановление

- **Формат** — один JSON `BackupDocument` (`format = "braineeapp.backup"`, `version = 2`; файлы версии 1 читаются): задачи (включая корзину, с длительностью и подзадачами — массив `subtasks` внутри задачи, D-39), папки, теги, привычки, профиль (со статусом, D-45), тема и акцент. Аватар не входит (D-16). Восстановление записывает тему, акцент и статус в UserDefaults.
- **Ручной экспорт** — «Профиль → Хранение данных», через «Файлы».
- **Автобэкап** — при уходе в фон, не чаще раза в 24 часа, последние 7 файлов в `Application Support/Backups/auto/` (D-04).
- **Восстановление** — только «заменить всё»: предпросмотр → подтверждение → текущее состояние сохраняется в `Backups/pre-restore/` → замена через `StoreContents.replace` → проверка по каждому `uuid` (D-20).
- **Обратная совместимость** — новые поля JSON читаются через `decodeIfPresent` со значением по умолчанию; старые бэкапы должны читаться.

## Экспорт в Календарь (EventKit)

Односторонний экспорт в собственный календарь «BraineeApp» (iCloud, иначе локальный), D-05/D-06/D-22/D-23:

- событие есть только у активной задачи с датой; без времени — на весь день, со временем — столько, сколько длится задача (по умолчанию 30 минут, D-40); выполненные и удалённые задачи из календаря убираются;
- после каждого `didChange()` и при возврате в приложение `CalendarExportService` сверяет весь список задач с календарём; неизменённые события не переписываются;
- связи «задача → событие» — служебный файл `Application Support/BraineeApp/calendar-links.json` (не SwiftData, не бэкап); потерянные связи восстанавливаются по метке `braineeapp://task/<uuid>` в url события; эта же ссылка открывает задачу в приложении;
- выключение экспорта только останавливает обновление; в событиях нет напоминаний (их присылает приложение).

### Встречи из Календаря (D-37)

Настройка «Профиль → Настройки → Календарь → Встречи из Календаря» (UserDefaults `calendarMeetingsEnabled`, по умолчанию выключена; при включении — запрос полного доступа, общий `EKEventStore` с экспортом). Во вкладке «Календарь» под задачами выбранного дня — блок «Встречи»:

- `CalendarMeetings` читает события всех календарей, кроме «BraineeApp», при показе дня, смене дня, возврате в приложение и по `EKEventStoreChanged`; ничего не сохраняет (ни SwiftData, ни файлы, ни бэкап) и сам никуда не передаёт (виджеты встреч не видят; наружу — только текст «Поделиться» по нажатию пользователя, D-43, а в LLM — обезличенное занятое время для «Плана дня» и два числа для «Итогов», D-44);
- правила дня — `CalendarMeetingRules` (чистые функции, тесты): «Весь день» первыми, дальше по времени начала; встреча, начавшаяся накануне, — «до ЧЧ:ММ»; слева время и продолжительность; подписи встречи (время, продолжительность, «Без названия», календарь) — `DayMeetingText`, общий для экрана и текста «Поделиться»;
- только просмотр: открыть, изменить или удалить встречу из приложения нельзя.

## «Поделиться» (D-38)

- Вкладка «Календарь»: «+» справа от «Поделиться» открывает форму новой задачи с заготовкой `TaskFormSnapshot.newTask(on:)` — срок выбранного дня без времени (прошедший день тоже можно, задача будет просроченной); сохранение — `TaskService.create`, без папки, то есть во «Входящие» (п. 40).
- Вкладка «Календарь»: кнопка справа от заголовка — `ShareLink` с текстом `DayTasksShareText.make` для выбранного дня: невыполненные задачи с дедлайном в этот день, время и название (без времени — «• Название»). Без описаний, тегов, папок, приоритетов, выполненных и просроченных. Под задачами — блок «Встречи» (`DayMeetingText.shareLine`: «09:30 · 30 мин — Планёрка (Работа)»), только если включены «Встречи из Календаря», есть доступ и в этот день есть встречи (D-43).
- Чат LLM: под ответами «План дня», «Итоги» и «Матрица» и в их контекстном меню — «Поделиться» с тем же текстом, что «Копировать» (`LLMAnswerText`).
- Приложение ничего не отправляет само и не ходит в сеть: получателя выбирает пользователь в системном меню.

## LLM (OpenRouter)

Вкладка «LLM» — чат с пятью режимами (выбор — меню над полем ввода). Ответы «Итоги», «План дня» и «Матрица» можно скопировать обычным текстом (`LLMAnswerText`, только буфер обмена). Провайдер — только OpenRouter, ключ — в Keychain, модель — строка в настройках (по умолчанию `openrouter/auto`). Каждый запрос отправляется отдельно, без истории; история чата живёт только в памяти до закрытия приложения.

| Режим | Что делает | Что уходит в OpenRouter | Меняет данные? |
|---|---|---|---|
| Задача | Фраза → черновик задачи | Текст, дата, часовой пояс, названия папок и тегов | Только после «Сохранить» в обычной форме |
| Разбор | Текст до 3000 символов → до 10 черновиков | То же | Каждый черновик — отдельно, через форму |
| Итоги | Цифры за сегодня или неделю + короткий комментарий | Только числа (посчитаны кодом); при включённых «Встречах из Календаря» — ещё число встреч и время в них (D-44) | Нет |
| План дня | Порядок задач на сегодня и советы | Номер, название, приоритет, время срока, просрочка задач на сегодня и просроченных (до 30); при включённых «Встречах из Календаря» — занятое время сегодня без данных встреч (`DayPlanService.busySlots`, до 20 промежутков, D-44); нужно согласие (`llmDayPlanConsentV2`) | Нет |
| Матрица | Для задач без срока: запланировать (на этой неделе / в этом месяце / позже), делегировать или убрать — с коротким советом (`MatrixReviewService`, D-42) | Номер, название, приоритет, квадрант матрицы задач без срока (до 30); отдельное согласие | Нет |

Как устроено:

- `LLMProvider` (протокол) → `OpenRouterProvider` (`URLSession`, тайм-аут 30 с). Ошибки (нет сети, ключ, лимит, модель, сервер, тайм-аут, битый или пустой ответ) превращаются в понятные сообщения; автоматических повторов нет, есть «Повторить».
- Ответ модели — JSON по схеме из инструкции; код всегда проверяет его сам (D-25). Теги и папки — только существующие; модель видит номера задач, а не `uuid`.
- Каждый запрос просит `reasoning: {effort: "low", exclude: true}`. Для бесплатных моделей (`openrouter/free`, `…:free`) лимит ответа ×4: все они рассуждающие и тратят лимит на рассуждения. Если лимит кончился раньше текста — отдельная ошибка с названием модели.
- «Профиль → Настройки → LLM»: ключ, модель, «Проверить соединение», остаток лимита ключа (`GET /api/v1/key`), отзыв согласий на «План дня» и «Матрицу».
- **Отладочная заглушка:** в Debug-сборке аргумент запуска `-LLMStub` подменяет OpenRouter готовыми ответами — ключ и сеть не нужны (см. [`TESTING.md`](TESTING.md)).

## Навигация

Вкладки: Задачи → Календарь → LLM → Привычки → Профиль. Календарь, LLM и Привычки включаются в «Профиль → Настройки → Панель вкладок». Матрица Эйзенхауэра — в «Профиль → Дополнительно», открывается листом со своей навигацией. Экраны вкладок не уничтожаются при переключении; открытый подраздел и поиск «Профиля» сохраняются при сворачивании и смене вкладки, повторное нажатие на вкладку «Профиль» возвращает в её корень (п. 41). Листы и запросы поверх экрана скрытой вкладки закрываются через `isTabActive` / `dismissOnTabLeave` (`Views/Components/TabActivity.swift`), чтобы переход из уведомления или виджета не оставил их поверх другой вкладки.
