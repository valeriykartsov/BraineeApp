## Как устроено сейчас

- SwiftData — **постоянное хранилище** `Application Support/BraineeApp/BraineeApp.store` (`ModelContainerFactory`, схема `SchemaV2`, V1 заморожена, `#Unique` на `uuid`). Это единственный источник правды. Старый путь (`Documents/BraineeApp/*.json` + Keychain-копии) и мигратор удалены в SD-6 (D-21); Keychain — только для секретов.
- Переход V1 → V2 (D-39): `SchemaUpgrade` при открытии хранилища — копия SQLite и снимок данных в `Application Support/Backups/pre-schema-v2/` → лёгкая миграция → сверка → маркер `Application Support/BraineeApp/schema-v2-migration.json`; бэкап не перезаписывается, повтор без дублей.
- Старт: `AppRootView` → `AppDataPersistence.bootstrap` (акцент при первой установке, `LegacyStorageCleanup` — удаление старых JSON/Keychain-копий, если есть маркер переноса `Application Support/BraineeApp/swiftdata-migration.json`, виджет). Хранилище при старте **никогда** не очищается. Откат на старую сборку не поддерживается (D-19).
- Любое изменение данных — только через сервисы `Domain/` (`TaskService`, `GroupService`, `TagService`, `HabitService`, `ProfileService`); они вызывают `modelContext.didChange()` (`AppSideEffects`: `save()` + виджет + уведомления). Во View не менять модели и не вызывать `didChange()` напрямую.
- Экспорт в Календарь (CAL-2, D-05/D-06/D-22): `Integrations/Calendar/`. Настройка «Профиль → Настройки → Календарь» (UserDefaults `calendarExportEnabled`). После каждого `didChange()` и при возврате в приложение `CalendarExport` сверяет все задачи с календарём «BraineeApp» (iCloud, иначе локальный): событие есть только у активной задачи с датой, неизменённые события не переписываются. Связи «задача → событие» — служебный файл `Application Support/BraineeApp/calendar-links.json` (не SwiftData, не бэкап); потерянные связи восстанавливаются по метке `braineeapp://task/<uuid>` в url события. В тестах (`refreshNotifications: false`) экспорт не запускается.
- Встречи из Календаря (D-37): `CalendarMeetings` читает события всех календарей, кроме «BraineeApp», для блока «Встречи» во вкладке «Календарь» (настройка `calendarMeetingsEnabled`). Только просмотр: встречи не сохраняются, не попадают в бэкап, LLM и виджеты.
- Бэкап: при уходе в фон `AutoBackup` пишет `BackupDocument` (формат ручного экспорта, D-16) в `Application Support/Backups/auto/` — не чаще раза в 24 часа, последние 7 файлов (D-04). Восстановление — «Профиль → Хранение данных» (`BackupRestore`, D-20): замена всех данных, перед ней текущее состояние сохраняется в `Backups/pre-restore/`. Замена и сверка хранилища с документом — `StoreContents`.
- LLM (D-24…D-33, D-42, D-44): `Integrations/LLM/` — `OpenRouterProvider` (единственный провайдер), сервисы режимов чата `TaskDraftService`, `InboxDraftService`, `ReflectionService`, `DayPlanService`, `MatrixReviewService`; экран — вкладка «LLM» (`Views/LLM/`). Ключ — Keychain (`SecretStore`), модель — UserDefaults (`LLMSettings`). LLM-код не получает `ModelContext` и не меняет данные: черновики сохраняются только через форму задачи и `TaskService`. Что можно отправлять наружу — строго по D-26/D-31/D-32/D-42/D-44; новые данные в запросах — только отдельным решением.
- Отладочные аргументы запуска (только Debug): `-LLMStub` — заглушка вместо OpenRouter, `-SeedDemoData` — демо-данные в пустое хранилище (`Debug/DemoDataSeeder.swift`), `-SeedDemoMeetings` — демо-встречи в Календаре устройства (`Debug/DemoMeetingsSeeder.swift`).
- Исключение (D-45): текстовый статус профиля — в UserDefaults (`profileStatus`) и поле `status` профиля в бэкапе, без новой схемы; при `SchemaV3` перенести в `UserProfile`.
- Новые поля в модели — новая версия схемы (`SchemaV3` + этап в `BraineeMigrationPlan`, V2 «заморозить» по образцу V1 в `Schema/Schema.swift`, D-17) и поле в JSON бэкапа только через `decodeIfPresent` + значение по умолчанию и `MyTasksDocument.normalizeRecords()` (старые бэкапы должны читаться).
- Флаг мягкого удаления в модели — `isSoftDeleted` (не `isDeleted`: конфликт с SwiftData); в JSON бэкапа он называется `isDeleted`.
- Зависимостей нет (только Apple SDK). Мин. iOS 18.2, Swift 5.

## Принципы

1. Offline-first: локальные функции не зависят от сервера, LLM и сети.
2. Внешний идентификатор сущности — `uuid`, не `PersistentIdentifier`.
3. Бизнес-правила — в одном месте (целевое: `Domain/*Service`), не во View и не в нескольких слоях.
4. Без серверной инфраструктуры и сторонних пакетов без явного решения в `docs/decisions.md`.
5. Одна задача бэклога за раз; не смешивать независимые подсистемы в одном изменении.
6. Только iOS (macOS/visionOS не поддерживаем). «Цели» и «фокус» — заметки Obsidian, не сущности приложения.

## Данные — строгие ограничения

- Не удалять и не перезаписывать пользовательские данные, хранилище SwiftData, бэкапы (`Application Support/Backups/`) и Keychain-записи без явного подтверждения владельца.
- Никакой очистки хранилища при старте (риск R1): `clearAllData` удалён в SD-3 и не должен возвращаться.
- Любая миграция: бэкап → копирование → проверка → маркер → переключение. Повторный запуск не должен создавать дублей.
- Секреты (API-ключи, токены) — только в Keychain; не в коде, логах, `Info.plist`, UserDefaults.

## Сборка и тесты (обновлено 2026-10-26)

Запуск — только через `scripts/test.sh` (полный лог в `$TMPDIR/braineeapp-test.log`, в консоль — ошибки, `✘` и итог):

```bash
scripts/test.sh                                   # все BraineeAppTests (~1–2 мин)
scripts/test.sh CalendarExportServiceTests        # только указанные наборы (имя struct)
scripts/test.sh --build                           # только компиляция
```

Скрипт сам берёт загруженный симулятор iPhone (иначе iPhone 16 / iOS 18.3.1; можно задать `BRAINEE_SIM_ID`), отключает параллельные клоны и сбор диагностики (`-collect-test-diagnostics never` — иначе после упавшего теста xcodebuild «висит» ~10 минут), прерывает прогон через 10 минут.

**Экономия времени и контекста (правила для агента):**
1. Не запускать `xcodebuild` напрямую и не выводить его лог целиком; при падении читать из полного лога только нужный фрагмент (`grep -n -A5 "<имя теста>"`).
2. Объём тестов по типу задачи (утверждено владельцем 2026-10-26):
   - **обычная** (не больше 2 коммитов) — один прогон в конце: все затронутые наборы одной командой (новые тесты + наборы изменённых типов), без отдельного `--build`; упал — чинить и перезапускать только упавший набор; **полного прогона нет**;
   - **сложная** (больше 2 коммитов или по запросу владельца) — то же + один полный прогон в фоне перед отчётом.
3. После правок только в `docs/`, `*.md`, `backlog.md` тесты не запускать. Не перезапускать прогон «для уверенности», если код не менялся.
4. Прогоны — в фоне; ждать уведомления о завершении, не опрашивать файл.
5. Симулятор — только для сложного UI: новые экраны, жесты, перетаскивание, прокрутка, системный UI (уведомления, Live Activity). Порядок, тексты и настройки, покрытые тестами, в симуляторе не проверять. Один проход, состояние — по данным.
6. Тесты не должны зависеть от текущего времени: «сейчас» — фиксированная дата или параметр (`now:`, `isOverdue(at:)`, `isDue(on:)`), а не `Date()` рядом с границей суток.
7. Ручная проверка в симуляторе: состояние — по данным (`sqlite3` по хранилищу, plist UserDefaults, файлы), а не по серии скриншотов; скриншоты — редко и с `scale` 0.3–0.4. Скриншот отстаёт примерно на одно действие. `Toggle`/`UISwitch` в симуляторе iOS 18 включается свайпом по переключателю, а не тапом; на iOS 27 не включается ни так, ни так — настройку UserDefaults задавать аргументом запуска (`-calendarMeetingsEnabled YES`).
8. Чат LLM в симуляторе — только с отладочной заглушкой: `xcrun simctl install <UDID> <.app>` и `xcrun simctl launch <UDID> valeravalera.BraineeApp -LLMStub` (ключ не нужен, сеть не используется). Ввод текста идёт через вставку: разрешить вставку в системном запросе; кириллица при вставке искажается — для заглушки содержание не важно. Ключ в `SecureField` так ввести нельзя. Перед первым нажатием дождаться конца заставки (~4 с). Путь к хранилищу меняется после переустановки — брать заново через `xcrun simctl get_app_container`. Если приложение не отвечает — сначала загрузка CPU (`ps`), а не новые скриншоты. UserDefaults приложения — `plutil -p <контейнер>/Library/Preferences/<bundle id>.plist` (не `simctl spawn … defaults read`: читает другой домен). Режим чата выбирается из меню (кнопка слева над полем ввода); данные для проверки удобнее готовить через форму задачи, чем вводом текста.

Тесты — Swift Testing (`import Testing`), в `BraineeAppTests/`, имена на русском `чтоПроверяем_ожидаемыйРезультат`, перед тестом комментарий; хелпер `TestHelpers.makeContainer()`.
`ModelContainer` в тестах хранить в свойстве тестовой структуры (`init() throws`), а не в локальной переменной: Swift может освободить её после последнего использования, и обращение к моделям роняет весь тестовый процесс.
В тестах сервисов передавать `onChange` (например, счётчик): настоящий `didChange()` пересчитывает уведомления асинхронно, и задача может обратиться к моделям уже освобождённого тестового контейнера.

## Git

- Основная ветка `main`; работа в отдельной ветке на задачу, слияние через PR.
- Коммиты и push — только по просьбе владельца; никогда force push в `main`.
- Сообщения: `feat(...)`, `fix(...)`, `docs(...)`, `test(...)`, `refactor(...)`.
- Не менять Bundle ID, signing, entitlements, App Group без запроса.
